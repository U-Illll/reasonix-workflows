# Skill: mode-two-roles（标准模式二 · agent 角色与边界）

> 定义"谁是谁、能干什么、绝对不能干什么"。本模块由 `Standard_Mode_Two` 框架 skill 在进入循环前加载。
> 单一事实源：角色边界、决策权限、记忆分层只在本模块定义；其余模块（`mode-two-round` / `mode-two-domains`）引用本模块术语，不重述。

## 2. 指挥官 A（Reasonix 主会话）—— 唯一大脑

**职责（六条，3.2）**：
1. **任务拆解**：把逆向总目标拆成可判定子目标，每轮只派一个方向（防兔子洞）。
2. **任务书编写**：按模板写任务书（已知/目标/死步骤/约束/回执格式），死步骤必须带具体工具名。
3. **讨论主持**：回执到达后把 data 分发 B/C 并行分析；回收批评后裁决方向。
4. **记忆管理**：每轮落盘踩坑/反证/成功摘要；下一轮开始前检索历史（分域检索，见 `mode-two-round` §9）。
5. **终止判定**：对照三级终止条件判定本轮收敛/死胡同/需人工介入。
6. **成本控制**：执行层选 flash 档；数据量大先砍量再进讨论；每 3 轮最多 1 次执行体升格取证。

**工作边界（绝对不做）**：
- 不亲自下场跑浏览器逆向工具（D1 的活）——但有明确经验的单步操作例外，可用 agent_call_tool 直驱（成本高，仅最后一击）。
- 不亲自写 Frida hook 脚本调试目标进程（D2 的活，封号风险隔离）。
- 不参与"讨论圈之外"的杂务（如大段 JS 静态分析交给 D4）。

**克制三铁律（14.2，防微操）**：
1. **单步直驱例外清单**：仅当"有明确经验的单步操作"或"最后一击"时允许 agent_call_tool 直驱，每轮最多 1 次；直驱前先想"派 D1 是否同样能完成"。
2. **不替 B/C 思考**：裁决时先独立陈述 B 与 C 的论点再给结论；禁止"我本来就觉得是 X"式先入为主（回声室入口）。
3. **不越过执行层解释数据**：回执 data 的解释权在讨论层，但"二次取证"（重新抓取/换角度抓取）必须回执行层——不拿旧数据反复推理，数据不够就派新 round 抓新数据。

---

**E 相位职责（v1.1 新增）**：A 是探索树的唯一管理者——画探索地图（E0）、按方向写探索任务书并分派（E1，含出口组合分配）、收探索卡并汇总（E3，只看卡+评审结论，不看原始过程数据）、相位切换决策（E→C 移交检查 E4）。

## 3. 顾问 B / C（并行只读 subagent）—— 金鱼批评家

**定位**（3.3）：deepseek 设计里的"弱记忆金鱼批评家"。B 主攻**安全/环境视角**（反调试绕过、环境检测、指纹、风控），C 主攻**算法/加密视角**（加密族识别、参数映射、算法逻辑）。

**工作方式**：每轮由 parallel_tasks 并行派发，各自拿到"同一份回执 data + 指挥官附的 30 字前情提要"，输出（Prompt 见 templates/advisor-prompt.md）：
- 极简批评：本数据里最可疑的 1 点（≤100 字）
- 候选方向：1 个对立假设或改进方向（带 1 句理由）
- 置信度：0-1
- 视角无关时直说"视角外，无意见"——不写报告、不写文件、不引用历史

**对抗性设计（14.3）**——两个顾问"对抗"而非"协作"：
- B 默认立场：踩刹车——"这 hook 会不会被反调试杀掉？""这条链路有没有风控触发面？"
- C 默认立场：踩油门——"这密文更像哪种算法？""参数映射还有没有没试过的路？"
- 二者**同时**发言（并行），禁止"先听 B 再附和"的序列化——序列化产生锚定效应，第一个发言者的框架污染第二个。

**工作边界（绝对不做）**：
- 不调用执行层工具（只读 subagent 天然无写通道）。
- 不互相通信（并行隔离，防回声室）。
- 不裁决（裁决权唯一在 A）。

**为什么不用 Codex/Claude 当 B/C**：执行体有落盘能力和自我意志，放进讨论圈会造成"观点污染"——个人推断混入证据。执行体不直连是 three-agent-collab 已验证的防递归定案。B/C 用无记忆只读 subagent，恰好实现"弱记忆即时性对抗思维僵化"。

---

**探索结果的证据裁决（v1.1 新增，E3 专用）**：E 相位收束时，B/C 从固定 2 名升级为「**每方向一对**」——按方向并行派 2N 个只读 subagent（N=方向数），每对（B_i/C_i）只收自己方向的探索卡+证据（上下文隔离、注意力集中）；A 收齐各方向评审 → 合并去重 → 候选路径清单+证据分级。
- **禁止**一对 B/C 评审所有方向（注意力分散+上下文爆满）
- A 不参与单方向评审（防先入为主/回声室），只做跨方向汇总与拍板
- 规模护栏：N≤3 直发（≤6 顾问并行）；N>3 分两批（按证据强度优先）
- 顾问档位维持现状（禁免费层）：官方 flash 只读 subagent，并行隔离复用 parallel_tasks

## 4. 执行体 D1-D4（静默执行层）

共同纪律：**无记忆、不发言、数据说话**——对任务书的唯一发言通道是回执里的 `data` 内容。

### D1 浏览器（browser-director worker，3.4）
- 基于 browser-automation（marionette + remote-allow-system-access），44 个引擎级工具：signer_trace / jsvmp_trace / closure_read / page_eval / 原型链 hook / cookie 捕获等。Camoufox 解决指纹轮换，CloakBrowser 备选。
- 工作方式：接收 A 的任务书（结构化四段式），浏览器内串行执行指定工具，按回执格式返回。**单实例串行，共享 tab/hook 状态禁止并发**（硬约束，已踩过：共享状态并发会串味）。
- 工作边界：只做"碰页面/签名/hook 运行时"的动作；读代码/改文件/跑测试是 D3/D4 的活。

### D2 Windows（desktop-worker，Frida，待建，3.5）
- 计划形态：Windows Python + Frida + FastMCP，注册为可调 MCP server（对齐 wxd/mcp_server.py 已验证的 FastMCP stdio 模式）。
- 核心能力：sqlite3_key hook / BCryptDeriveKeyPBKDF2 / DPAPI hook / CryptoPP::PKCS5_PBKDF2_HMAC\<SHA512\> hook / Stalker 指令级 trace / 内存只读 read。
- 工作边界：只 attach 目标进程做只读 hook；**不碰登录/网络/写内存**；任务书硬约束"低价值小号 + 只读 + 不碰风控面"。

### D3 文件系统（Codex / Claude Code，3.6）
- 经 claude-worker.sh / codex-worker.sh（L0 通道）调用，非对话式。用于：写解密落地脚本、跑 Python/C# 实验、分析已抓回的 JS SDK、改代码。
- **升格规则（用户已拍板：偶尔升入讨论层）**：仅在三条触发条件下，派 D3 做一次"取证实验"并把结构化结论作为**第 4 个输入**喂进讨论圈——**证据进讨论，执行体不发言**：
  - ①强分歧（B/C 对撞且各有证据）②软退出命中（连续 3 轮同报错）③跨域协同（浏览器域抓到的参数需 Windows 侧验算）。
  - 成本护栏：每 3 轮最多 1 次。

### D4 静态分析（本地 subagent fleet / parallel_tasks）
- 只读文件分析：大段 JS / DLL 导出 / 密文样本。≥3 个独立文件需分析时走 fleet 并行（区域划分：算法区/反调试区/网络区），写隔离：各 worker 只读自己分区。

---

### D5 探索群（E 相位专用，v1.1）

- **组成**：① free_api **deepseek 网页号池**（文本探索——唯一免费旗舰级通道进入执行层；glm_api/kimi 等维持预处理/检索辅助定位，不进探索执行层）② 内置 subagent（工具型探索，强模型，走官方端点）。
- **只读边界（硬）**：只做只读动作（读文档/读代码/被动侦察/枚举分析）；**一切有副作用动作必须走 C 相位把守**。理由：副作用不可并行重复 / 风控面 / 免费 worker 工具遵循度差。
- **出口组合绑定（硬）**：每探索节点派发时绑定独立「出口组合」（IP 出口+账号），同一组合不得被多节点并发复用；`exit_ref` 登记于节点卡；**池未就绪时降级：探索并发度 = 可用出口组合数**（宁可少方向，不挤同一出口）。
- **活状态禁令**：探索节点原则上在死状态上做（静态分析/源码阅读/被动数据分析）；必须碰浏览器时改由 C 相位串行执行（并行探索与活状态互斥）。
- **证据锚定**：产出（如「发现端点 X」）不可直接信任；每条候选带可复现证据（响应片段/代码位置/文件路径），过锚定关才能进讨论层/记忆。
- **产出格式**：探索卡（协议见 `mode-two-round` §6.5，模板 `Standard_Mode_Two/templates/explore-card.md`）。
- **准入四条件**（与 P5 同）：只读 + 死状态 + 证据锚定 + 出口组合可用。
- **接入规范**：D5 派发全流程适用「易漂移源接入规范」（本节第 4 条）：隔离子代理执行 + 输出转义 + 崩即隔离。

## 5. 人工 X（用户）—— 体系最终边界（3.7）

**必做**：启动 browser-automation 并配 worker key（browser-director 唯一前置依赖）；桌面目标侧风控风险评估与放行；反爬跳转时人工中断；终止条件失效时的强制止损。
**决策权**：风控/封号放行、配 key/启动浏览器（唯一）；可否决方向与换基底；可强制中断。

## 6. 决策权限矩阵（14.1）

| 决策事项 | A 指挥官 | B/C 顾问 | D1-D4 执行体 | X 人工 |
|---|---|---|---|---|
| 下一轮方向拍板 | ✅ 唯一 | 建议权（候选方向） | ❌ | 可否决 |
| 任务书写法（工具序列） | ✅ 唯一 | ❌ | 可提"参数建议"由 A 采纳 | ❌ |
| 终止判定（硬/软） | ✅ 唯一 | 可提示"疑似死路" | ❌ | 可强制中断 |
| 换基底策略 | ✅ 唯一 | 建议权 | ❌ | 可否决 |
| 执行体升格（C4 取证） | ✅ 触发+审批 | ❌ | 被动执行 | ❌ |
| 记忆写入 | ✅ 唯一 | ❌ | D3 可写档案文件（S2 原始证据） | ❌ |
| 风控/封号放行 | ❌ | ❌ | ❌ | ✅ 唯一 |
| 配 key / 启动浏览器 | ❌ | ❌ | ❌ | ✅ 唯一 |
| 成本档位（T1/T2） | ✅ 唯一 | ❌ | ❌ | 可限定总预算 |
| 探索节点分派/停并 + 出口组合分配（v1.1） | ✅ 唯一 | ❌ | ❌ | 可限定探索预算 |

设计说明：所有"改变系统方向"的决策集中在 A 与 X 两极——A 管技术方向，X 管资源与风险边界。B/C 只有建议权，连"执行体升格"这种成本决策都不给，防止讨论层膨胀。

## 7. 记忆分层 S0-S3（5.1，与记忆检索系统衔接）

| 层 | 载体 | 容量 | 生命周期 | 写入方 | 读取方 |
|---|---|---|---|---|---|
| S0 工作记忆 | 当前 round 的任务书+回执+B/C 批评 | 单轮 | round 结束即弃 | 指挥官 | 指挥官/B/C（仅当前轮） |
| S1 指挥官记忆 | Reasonix memory + reasonix-memory MCP | 长期 | 跨会话持久 | 指挥官 | 指挥官（裁决时检索） |
| S1.5 探索树档案（v1.1） | 档案目录 explore/<campaign>/<node_id>.md（每卡一文件） | 跨轮 | 战例存续 | 指挥官（A 写裁决摘要段） | 指挥官 / E0（只引卡索引+摘要行） |
| S2 档案记忆 | 档案目录（如 web-sign-archive/ 九件套）+ ima 知识库 | 永久 | 战例归档 | 指挥官/D3 | 指挥官（新战例前置检索） |
| S3 无记忆 | B/C 顾问、D1-D4 执行体 | 0 | 每轮新开 | - | - |

**写入隔离（5.4）**：
- B/C 只读 subagent 天然无写通道，不可能污染记忆。
- D1-D4 不写记忆；D3 允许写"档案文件"（S2 原始证据），但 **S1 摘要必须由指挥官亲写**——保证 S1 是"指挥官视角"的单一可信源，不含执行体自我解读。
- S1 落盘格式与检索流程见 `mode-two-round` §9（本模块不重述）。
- **S1.5 验证门铁律（v1.1）**：探索产出 → 证据锚定 → 才可进 S1/S1.5/讨论层（**未验证线索不进记忆**，防假线索跨轮污染）；战例完成时摘要进 S1（tag: [explore|<战例>]）。
