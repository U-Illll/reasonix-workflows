# 复盘 Prompt（Standard_Mode_Two / templates）

> 用途：①每 5 战例复盘（19.2）②失败战例的"失败评审"（19.3）。复盘结论写入平台层 skill（本 skill 集随版本迭代），同时归档 ima「逆向经验库」。

## 复盘正文（F.3 正式版）

```
复盘对象: {战例名} | 结束方式: {成功/不可行/放弃}
四问:
  1) 任务书"已知"是否充分,执行层是否裸奔探索?
  2) B/C 是否真的对抗了?还是都在附和?
  3) 换基底时机是否得当?太晚/太早?
  4) 终止条件是正确触发,还是误触发?
输出: {经验清单(可写入平台层 skill)} {四轴触发条件修正建议} {记忆模板改进建议}
```

## 战例级 KPI（19.1，复盘时核算）

| 指标 | 计算 | 目标 |
|---|---|---|
| round 收敛率 | 成功战例的平均 round 数 | ≤8 |
| 换基底次数 | 软退出触发次数/战例 | ≤2（超过=任务书质量问题） |
| 死路排除效率 | 每排除一条死路的平均 round 数 | ≤2 |
| 记忆命中率 | 裁决引用 S1 的轮次占比 | ≥50% |
| 漂移率 | drift 回执/总回执 | ≤10% |
| 成本 | 每战例 token 总量（分档统计） | 记录基线 |

## 每 5 战例复盘动作（19.2）

1. 汇总 S1 全部死路证明 → 提炼"本平台常踩的坑"清单。
2. 检查四轴速判命中准确率（哪些模式选型后无效 → 调整触发条件）。
3. 检查记忆模板是否需新增字段（出现无法用现有标签表达的踩坑时）。
4. 复盘结论写入平台层 skill。
